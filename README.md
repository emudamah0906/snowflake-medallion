# Insurance Claims Medallion — Snowflake

A Bronze → Silver → Gold pipeline in Snowflake for P&C insurance policy, claims and broker data.
Raw CSV extracts land untyped, get conformed and deduplicated, and are served as a dimensional
model with a Type 2 slowly-changing policy dimension. Promotion between layers is gated by a
reconciliation check that fails the run when control totals drift.

## Architecture

```
CSV extracts ──► @STG_RAW ──► BRONZE ──► SILVER ──► GOLD
                              (raw,      (typed,    (star schema,
                               untyped,   deduped,   SCD2 dim_policy,
                               append)    conformed) fact_claim)
                                              │
                                              └──► OPS (quarantine, reconciliation)
```

**Why land raw and untyped.** Bronze stores every column as text with load metadata attached. A
malformed date cannot fail the load, and when transformation logic changes later the history can be
replayed without going back to the source system.

**Grain of the fact table.** One row of `fact_claim` = one claim. Decided before any DDL was
written.

## Source data

Synthetic, generated by [`data/generate_data.py`](data/generate_data.py) — stdlib only, seeded for
reproducibility. Defects are deliberate, so every downstream layer has real work to do:

| File | Rows | Planted defects |
|---|---|---|
| `brokers.csv` | 51 | 1 exact duplicate, ~4% null email, inconsistent region casing |
| `policies_snapshot_01.csv` | 5,025 | ~0.5% duplicates, ~2% malformed dates, mangled product casing |
| `policies_snapshot_02.csv` | 5,025 | same, plus **602 policies with changed status/premium** |
| `claims.csv` | 12,060 | 60 duplicates, ~1% orphan `policy_id`, zero/negative/outlier amounts |

The two policy snapshots are a daily-extract pattern. Loading them in sequence is what exercises
SCD Type 2 — the 602 changed policies should each end up with one closed row and one current row.

## Layers

| Layer | Does |
|---|---|
| **Bronze** | `COPY INTO` from stage, all columns `VARCHAR`, plus `_loaded_at` and `_source_file` |
| **Silver** | `TRY_CAST` typing, dedupe via `ROW_NUMBER()`, conform casing and codes, bad rows to `OPS.QUARANTINE` |
| **Gold** | `dim_broker`, `dim_date`, `dim_policy` (SCD2), `fact_claim` |
| **OPS** | Quarantined rows, reconciliation results, run audit |

## Running it

```bash
python3 data/generate_data.py
```

Then, in a Snowflake worksheet, in order:

| Script | Stage |
|---|---|
| `sql/00_setup.sql` | Warehouse, database, schemas, file format, stage |
| `sql/01_bronze.sql` | Raw load |
| `sql/02_silver.sql` | Typing, dedupe, conforming |
| `sql/03_gold.sql` | Star schema and SCD2 |
| `sql/04_streams_tasks.sql` | Incremental promotion |
| `sql/05_reconciliation.sql` | Control-total gate |

Upload the CSVs to the stage with SnowSQL, or drag them in via Snowsight:

```sql
PUT file://<path>/data/*.csv @INSURANCE_DEMO.BRONZE.STG_RAW AUTO_COMPRESS=TRUE;
```
